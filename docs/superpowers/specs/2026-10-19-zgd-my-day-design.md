# «Мой день» ЗГД: вкладки Сегодня · Дирекции · Динамика · Поручения

## Контекст
«Мой день» у ЗГД сейчас — только списки «что горит». Владелец хочет управленческий инструмент: за несколько минут понять, какая дирекция теряет управляемость,
где срываются сроки, какие поручения требуют вмешательства. Решения владельца: **4 вкладки внутри «Моего дня»**, **только подтверждённые директорами данные**
(отправленные справки и «Обновить для ЗГД»), графики — свои SVG без библиотек. Замечания владельца к первому варианту приняты целиком: светофор не должен «врать»
на малых выборках, отсутствие справки — отдельный статус, история не переписывается, у каждой метрики зафиксированы определение и знаменатель,
сегменты поручений взаимоисключающие, каждый цвет объясним числами, из любой карточки — переход к задачам.

Попутно (обнаружено после выкладки 684a7c6): в CI падает шаг «Типы» — `Cannot find name 'LayoutProps'` (тип генерирует Next в `.next/types`).
Исправление первым коммитом: в `.github/workflows/ci.yml` перед `tsc` выполнить `npx next typegen`. Браузерные тесты в CI уже зелёные.

## Источники данных (не меняются, только читаются)
- `memo_versions` — отправленные справки (append-only, ревизии; возвращённая помечена `returnedAt`). `item_publications` — подтверждения «Обновить для ЗГД» (append-only).
- Состояние задачи на момент T = последнее подтверждённое к T (логика `buildZgdTracker`, `lib/tracker-sent.ts`). Удалённые дирекцией задачи у ЗГД не учитываются (как в `loadSentTracker`).
- **История не переписывается:** точка недели = последняя невозвращённая ревизия справки этой недели. Если справку вернули и отправили заново, точка берётся из новой ревизии
  и помечается «исправлено: ревизия N, дд.мм, кто отправил» — исправление видно, а не тихо подменено.
- Доступ — на сервере: новый маршрут отвечает только роли EXECUTIVE (остальным 403), считает только из подтверждённых источников.

## Определения метрик (фиксируем в коде и в подсказках)
Все даты — по Москве, «сегодня» = `mskDay`. Активная задача — колонка не «Выполнено» и не «Не актуально».
| Метрика | Определение | Знаменатель / примечание |
|---|---|---|
| Просрочено | активная, подтверждённый текущий срок < даты снимка | из активных; показываем «x из y» и %. Отдельно — «сорван исходный срок» (originalDeadline < даты снимка) |
| Срок сдвигали (30 дн.) | число подтверждённых переносов срока на более поздний за 30 дней | только утверждённые (видимые ЗГД); просьбы о переносе не считаем |
| Без движения 14+ дн. | активная, подтверждённые статус/срок/ответственный/комментарий не менялись 14+ дней | изменение = событие в истории ЗГД, не комментарий |
| Выполнено вовремя (30 дн.) | подтверждено «Выполнено» за 30 дней и дата выполнения ≤ подтверждённого срока на момент выполнения | знаменатель — выполненные за 30 дней **со сроком**; «без срока: k» отдельно |
| Свежесть данных | дата последнего подтверждения дирекции (справка или «Обновить для ЗГД») | старше 10 дней → статус «Нет актуальных данных» |

## Вкладка «Дирекции» — «Где ситуация хуже нормы?»
Карточка на дирекцию: светофор по доле просрочек среди активных (зелёный < 5 %, жёлтый 5–15 %, красный > 15 %), **всегда с числами** «2 из 10»;
при активных < 10 — пометка «малая выборка»; при устаревших данных вместо цвета — серый статус «Нет актуальных данных · по состоянию на дд.мм»
(это прозрачность отчётности, не оценка исполнения). Ниже в карточке: сорван исходный срок, переносы за 30 дн., без движения, выполнено вовремя «n из m»,
мини-график просрочек за 12 недель. Каждый показатель — подсказка с определением. Под карточками — полосы «доля просрочек» (сортировка: худшие сверху,
дирекции без актуальных данных — отдельной группой внизу). Нажатие на карточку → `/tracker?org=<id>` (в трекер ЗГД добавляется фильтр по дирекции в адресе,
как остальные фильтры `filtersToParams`).

## Вкладка «Динамика» — «Становится лучше или хуже?»
Линии за 12 последних недель, по линии на дирекцию; переключатель показателя: «Просрочено на момент справки» / «Выполнено за неделю» / «Новых задач за неделю».
Интервал и источник фиксированы и подписаны («12 недель · по еженедельным справкам») — переключение показателя их не меняет. Неделя без справки — разрыв линии и
пометка «справки не было» (не ноль). Исправленная точка — с обводкой и подсказкой (ревизия, дата, автор). Легенда — щелчок скрывает/показывает линию.
Под графиком — «Показать таблицей» (те же числа текстом: доступность и проверяемость).

## Вкладка «Поручения» — «Что не исполнено и где нужно вмешательство?»
Набор: поручения ЗГД (origin ZGD, assignedById = я) и задачи «на контроле». **Сегменты взаимоисключающие**, по порядку проверки:
выполнено (с отметкой «в срок / с опозданием») → отменено → сорвано (активное, срок < сегодня) → срок ≤ 3 дн. → в срок.
Полоса по каждой дирекции из этих сегментов с числами. Таблица: задача, дирекция, срок (и исходный, если переносили), переносов, дней в работе, статус;
сорванные сверху; строка → карточка задачи в трекере. Сверху: «среднее время исполнения» = от `assignedAt` до подтверждённого «Выполнено», только завершённые
за 90 дней, показываем «n поручений» (незавершённые в среднее не входят).

## Вкладка «Сегодня» — как сейчас
Запросы без ответа, просрочено, срок скоро, мои поручения в работе, непрочитанный чат (`lib/today.ts`).

## Устройство
- `lib/zgd-analytics.ts` — чистые функции: снимок дирекции на дату, метрики (таблица выше), недельные точки, сегменты поручений. Без базы и интерфейса.
- `lib/zgd-analytics.test.ts` — граничные случаи: нет задач, малая выборка, нет справки, устаревшие данные, перенос срока (утверждённый), выполнено после срока,
  без срока, возврат и повторная отправка справки (точка помечена, старая не меняется), взаимоисключение сегментов поручений.
- `app/api/today/zgd/route.ts` — только EXECUTIVE; читает `loadZgdSources` / публикации (`lib/tracker-load.ts`), отдаёт готовые числа.
- Интерфейс: `components/TodayView.tsx` — вкладки (`?tab=`, только у ЗГД); `components/today/{DirectoratesTab,TrendTab,OrdersTab}.tsx`;
  графики `components/charts/{Sparkline,BarList,LineChart,StackBar}.tsx` — SVG с `<title>`/`aria-label`, подсказки через существующий `Tooltip`.
- Трекер: фильтр `org` (не `dir` — он занят переключателем дирекции админа) в `lib/tracker.ts` (`TrackerFilters`, `filtersToParams/FromParams`) и `TrackerView` для ЗГД.

## Проверка и приёмка
- Юнит: все метрики и граничные случаи выше. E2E API: маршрут 403 для не-ЗГД; изменение задачи без «Обновить для ЗГД» не меняет чисел; после подтверждения — меняет;
  возврат и повторная отправка справки — точка недели помечена ревизией.
- Playwright: вкладки ЗГД открываются (1300 и 375), карточка дирекции ведёт в трекер с фильтром, «Показать таблицей» показывает числа, без 5xx и горизонтальной прокрутки.
- Критерии приёмки владельца: числа воспроизводимы из подтверждённых источников; исторические точки не меняются незаметно; каждый красный/жёлтый объясним числами
  и правилом; из проблемной карточки — к задачам без ручного поиска.
- tsc, eslint, vitest, e2e, test:ui; CI зелёный; push → READY через `list_deployments`; коммиты с `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Миграций нет.
