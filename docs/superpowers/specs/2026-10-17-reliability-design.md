# Проект 1 из 4: «Надёжность» — автопроверка при push, браузерные тесты, журнал ошибок прода

## Контекст
Владелец попросил продумать, чего не хватает проекту. Выбраны все 4 направления, порядок утверждён:
**1. Надёжность → 2. Уведомления вне сайта (push через PWA) → 3. Аналитика для ЗГД и директоров → 4. Работа с задачами**
(подзадачи, повторяющиеся задачи, файлы, календарь, сохранённые виды, Ctrl+K). Каждый — отдельный цикл «дизайн → план → реализация».

Почему надёжность первой: тесты (vitest 376 юнит, 180 e2e API) запускаются только на моём ПК; ошибки интерфейса находятся вручную
(«Удалённые» не там, полоса прокрутки, пропавшая иконка); о сбоях на проде никто не узнаёт сам. Резервные копии уже есть (`.github/workflows/db-backup.yml`).

Решения владельца: журнал ошибок — **свой, в нашей базе** (без внешних сервисов); браузерные тесты — **да, дымовые по ролям**;
при провале CI — **выкладывать как сейчас, но сигналить** (красный крестик и письмо GitHub). Все три раздела дизайна одобрены.

Первым действием после выхода из режима плана: сохранить этот дизайн как `docs/superpowers/specs/2026-10-17-reliability-design.md` и закоммитить (так требует процесс brainstorming), затем — план реализации и работа.

## A. Автопроверка при каждом push — `.github/workflows/ci.yml`
- Триггер: push и pull_request в `master`; `concurrency` — отменять устаревший прогон той же ветки.
- Временная PostgreSQL как `services: postgres` (версия как у Neon), `DATABASE_URL` на неё; Node из `.nvmrc`/`package.json`, кэш npm.
- Шаги: `npm ci` → `npx prisma migrate deploy` → `npm run db:seed` (prisma/seed.ts) → `npx tsc --noEmit` → `npm run lint` → `npm test` → `npm run test:e2e`.
- Секреты не нужны (база временная). `AUTH_SECRET`/прочие обязательные переменные — тестовые значения прямо в workflow.
- **Риск:** часть e2e опирается на данные, которых нет в чистой базе (локальная копия сделана `db:pull`): например, «первый действующий директор», статусы. Решение: прогнать на чистой базе, найти такие места и сделать тесты самодостаточными (создавать нужное в `beforeAll`), при необходимости дополнить `prisma/seed.ts` справочниками (статусы с колонками трекера, «На стопе»). Тесты, которые нельзя сделать самодостаточными, — не допустимы.
- Провал → красный статус коммита + письмо GitHub; Vercel выкладывает как раньше.

## B. Браузерные тесты интерфейса — Playwright
- `@playwright/test` (devDependency), `playwright.config.ts`, тесты в `e2e/ui/*.spec.ts`; запуск `npm run test:ui`. В CI — отдельная задача после A: `next build` + `next start` на той же временной базе, Chromium.
- Учётки: `e2e/ui/setup.ts` создаёт в базе временную дирекцию, директора, двух руководителей, ЗГД (случайные пароли, хеш через `lib/auth.ts`), задачи с разными статусами/сроками; вход через `/api/auth/login`, сохранение `storageState` на роль.
- ~15 дымовых сценариев, каждый на 1300×900 и 375×800:
  вход трёх ролей и меню по роли (нет «Удалённых» в шапке таблицы; «Мой день» первым); таблица открывается и ищет;
  трекер — список/доска/таймлайн, плашка-фильтр колонки, «⋯» и меню действий, нет кнопки «Сегодня»;
  карточка задачи открывается, «Обсудить» открывает чат по задаче; чат — круг над шаром Оперативщика, окно, написать, создать группу;
  «Мой день» показывает разделы; нет ошибок в консоли браузера и ответов 5xx за сценарий; нет горизонтальной прокрутки страницы на 375.
- При падении — скриншот и трасса Playwright сохраняются артефактом Actions (7 дней).

## C. Журнал ошибок прода
- Миграция (добавляющая): `app_errors(id, fingerprint UNIQUE, source SERVER|CLIENT, route, message, stack, role, count, firstAt, lastAt)`.
  `fingerprint` = хеш(source + маршрут + сообщение + первая строка стека) — одинаковые ошибки склеиваются (`count + 1`, `lastAt`).
- Что пишем: маршрут без параметров адреса, текст ошибки (обрезка 500), первые 8 строк стека, роль. **Не пишем** тексты задач, тела запросов, e-mail, id пользователей.
- Сервер: `lib/api-guard.ts` `withApiErrors` — в `catch` для необработанных ошибок вызывает `recordError` (ошибка записи журнала не роняет ответ, сам ответ 500 как раньше).
- Браузер: `app/error.tsx` и `app/global-error.tsx` — страница «Что-то пошло не так» с «Повторить» вместо белого экрана; плюс `window.onerror`/`unhandledrejection` в клиентском компоненте рядом с `PwaRegister`; отправка `POST /api/errors` (только вошедшие; `burstLimited` 10/мин на человека; размер тела ограничен).
- Админ (`ADMIN`, `SYSTEM_ADMIN`): Настройки → вкладка «Ошибки» — список (последние сверху, счётчик, первая/последняя дата, маршрут, роль), «Отметить решённой» (удаляет запись).
- Cron (`app/api/cron/reminders/route.ts`, ежедневно): если за сутки появились новые отпечатки — уведомление админам «За сутки новых ошибок: N» со ссылкой на вкладку; уборка записей с `lastAt` старше 90 дней. Обе операции — в `try/catch`, как уборка уведомлений.
- Миграция на боевую — через Neon HTTP до push (как раньше), время точки восстановления запомнить.

## Переиспользуем

`hashPassword` (lib/auth.ts — для учёток Playwright), cron-маршрут и шаблон уборки `pruneNotifications`, вкладки Настроек (app/settings), схема e2e-учёток и уборки из `e2e/api.e2e.ts`.

## Проверка
- Локально: `tsc`, `eslint`, `vitest`, `npm run test:e2e`, `npm run test:ui` (Playwright на локальной базе).
- CI: push в отдельную ветку → оба задания зелёные; намеренно сломанный тест в ветке → красный статус и артефакт со скриншотом; ветку удалить.
- Журнал: локально бросить ошибку в тестовом маршруте и в браузере → записи появились, повтор склеился, вкладка «Ошибки» показывает, cron создал уведомление админу; e2e на права (`/api/errors` без входа — 401, чужой роли вкладка недоступна), на отсутствие личных данных в записи.
- Выкладка: миграция на боевую → push → READY через `list_deployments`; на проде открыть «Ошибки» админом (временная учётка, потом удалить).
