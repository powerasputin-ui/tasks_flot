Источник: `source-data/Флот-приобретение и коммерция.xlsx`, лист `Трекер` (142 строки данных, заголовки в строке 8), справочные значения также в листе `Справочник`.

Реальные колонки листа `Трекер` (строка 8): `Запись | Сегмент | Трек | Судно / Объект | Стоимость (Оценка) | Привлекательность / потребность | Дата | Идея утилизации / задача | Срок | Ответственный | Статус | Опер | Комментарии к статусу | стр | Нед`.

Тип записи (`Запись`) принимает значения `Трек` / `Задача` / `Судно` — это разделитель для Track/Task/VesselOption в одной плоской таблице. Принадлежность Task/VesselOption к Track определяется НЕ отдельным ID, а совпадением пары (Сегмент, Трек-название) со строкой типа `Трек` выше. Это нормально для импорта (раздел 52), но требует явного шага сопоставления при маппинге.

## UNRESOLVED BUSINESS RULE #1 — Deadline на уровне Track

**Что неизвестно:** У 1 из 25 Track (`Многофункциональная баржа / кабелеукладчик`, строка 9 Excel) заполнено поле `Срок` (06.08.2026). У остальных 24 Track это поле пусто. Модель ТЗ (раздел 11) не содержит `deadline` для Track — оно есть только у Task (раздел 12).

**Почему важно:** Если это не опечатка/артефакт ручного заполнения Excel, а осознанная бизнес-практика ("у трека может быть свой срок, отдельно от задач"), схему БД придётся менять.

**Вариант A:** Это опечатка/остаток от копирования строки. Track не имеет deadline. При импорте это значение отбрасывается с предупреждением validation report (раздел 53).

**Вариант B:** У Track должно быть собственное поле deadline (например, "плановая дата решения по треку").

**Что требуется подтвердить:** у бизнес-заказчика (Куратор/Руководитель) — есть ли смысл "срок трека", отдельный от сроков его задач.

**Принятое решение для Phase 1:** Вариант A (Track без deadline, как в ТЗ). Значение из Excel логируется в отчёт импорта как аномалия, не переносится в БД.

## UNRESOLVED BUSINESS RULE #2 — Owner на уровне VesselOption

**Что неизвестно:** У 2 из 24 VesselOption в исходных данных фактически не заполнено поле "Ответственный" (в реальности 0 из 24 — Owner всегда None), но 4 из 25 Track имеют Owner, а модель ТЗ (раздел 15) не содержит `ownerId` у VesselOption вообще.

**Почему важно:** Если куратор захочет назначать ответственного за конкретный вариант судна (а не за весь трек) — понадобится новое поле.

**Вариант A:** VesselOption не имеет ownerId (как в ТЗ) — ответственность всегда на уровне Track.

**Вариант B:** Добавить `ownerId` в VesselOption.

**Что требуется подтвердить:** у бизнес-заказчика.

**Принятое решение для Phase 1:** Вариант A — строго по модели ТЗ, ownerId у VesselOption не добавляется.

## UNRESOLVED BUSINESS RULE #3 — Смысл колонки "Дата" (отдельно от "Срок")

**Что неизвестно:** В листе есть колонка `Дата` (G), отдельная от `Срок` (I, = deadline). У 30 из 142 строк она содержит конкретную дату (28× `02.07.2026`, 2× `22.07.2026`), у остальных — `"-"`. Смысл этого поля в ТЗ не описан ни для Track, ни для Task, ни для VesselOption.

**Почему важно:** Может быть это дата последнего обновления/дата встречи/дата создания задачи — если это реальное бизнес-поле, для него нужно место в модели (например, `createdAt`, если это фактическая дата появления записи, а не `deadline`).

**Вариант A:** Технический артефакт таблицы (дата последней ручной правки строки), не переносится как бизнес-поле — используется только `createdAt` системы на момент импорта.

**Вариант B:** Это самостоятельное бизнес-поле ("дата события/дата фиксации"), которое нужно сохранить отдельно.

**Что требуется подтвердить:** у бизнес-заказчика.

**Принятое решение для Phase 1:** Вариант A — значение не переносится в структурированные поля, при необходимости сохраняется как часть комментария/audit при импорте, но не как отдельное поле схемы.

## Служебные (не бизнес) артефакты, отбрасываемые при импорте

* Колонка `стр` — совпадает с физическим номером строки Excel, технический артефакт, не переносится.
* Колонка `Нед` (Неделя) — почти всегда пусто, ИЛИ должна пересчитываться по правилу раздела 14 (`deadlineWeek` от `deadline`), а не браться из исходника (раздел 105, запрет №7: не использовать чужой источник недели вместо вычисления от deadline).
* Строки со значением `Сегмент = None` у 2 Track (`Консолидация деятельности Газпром флот`, `Расстановка флота 2027`) — попадают в отчёт импорта как предупреждение "Неизвестный/отсутствующий Segment" (раздел 53), сегмент для них должен быть подтверждён вручную куратором до импорта, Track не должен получать случайный сегмент.
